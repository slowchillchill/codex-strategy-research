# 策略研究与探索

只在用户显式调用本 skill 后启用研究工作流。同一研究轮次的后续交接沿用既有授权。安装或维护本 skill 不启动研究；不从旧作业、旧预算或一句没有对象的“批准”推断新任务范围。

研究主会话及全部子角色对业务代码仓库只读，不修改任何仓库文件，不提交、推送、开 PR 或合并，也不自行转为开发组。研究材料只写入分配的仓库外目录；研究主会话在授权内维护 Issues／Projects。工程问题先核实并向用户汇报，由用户审查后另行签发开发任务。

先读取目标仓库适用 `AGENTS.md` 和当前请求涉及的合同。将此 `SKILL.md` 的真实文件路径解析到完整源仓库：本文件位于 `skills/codex-strategy-research/`，其上两级为研究源根目录。安装必须保留完整源仓库；缺失时报告路径缺口，不猜测另一副本。

完整读取[共同研究流程](../../research/research-workflow.md)，按本次路线读取：

- A：[人工规则研究](../../research/rule-based-research.md)。
- B：[学习策略研究](../../research/learning-based-research.md)。
- 检索互联网、读取知识库或借鉴方法时：[研究资料与方法借鉴](../../research/evidence-sources.md)。
- 出现实现偏离或核心能力缺口时：[工程交接](../../research/engineering-handoff.md)。

主会话担任研究负责人。先恢复当前真实停点、研究问题、已批准范围、数据用途及剩余总预算，再持续完成可执行工作。在授权范围内自主安排配置、实验、分析和普通准备；需要裁决时先核实事实并给出具体方案。不能把提案、方法审查或数据日期用途批准当作运行授权。

按需要使用 `research-designer`、`experiment-runner` 和 `research-reviewer`。交接提供研究源路径与版本、研究 Issue 和授权、只读源码与产物身份、仓库外目录、适用方法与资料绑定、预算和产物责任。不要派生开发角色来代替研究角色或处理缺陷。若当前会话没有新角色，可用职责相同的普通子代理并加载对应模板；角色不可用不授权省略必要独立审查。新角色注册须在新会话核验，skill 不会切换当前模型或权限。

研究计划、方法依据、进度、结论和交接写入所属研究 Issue，Projects 展示状态，详细证据在仓库外留存。本仓库不接收真实行情、模型、训练结果、私有绑定或认证材料。按问题自主使用互联网和项目知识库，不把收录或论文结论当作本项目已验证事实。现有请求、反馈、NOE、Ledger 和报告能回答问题时直接复用；缺口按最小补充和工程边界处理。
