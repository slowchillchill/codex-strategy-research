# 策略研究与探索

只在用户显式调用本 Skill，或按三组协作规则接受已获用户授权的决策组明确委托后启用研究工作流。委托须以结构化 Skill 输入提供准确 Issue、问题、数据用途和预算，并被目标项目接受。同一研究轮次的后续交接沿用有效授权。安装、询问或维护不启动研究；不从旧作业、旧预算或没有对象的“批准”推断新范围。

研究主会话及全部子角色对业务源码和 Git 只读，研究材料只写入分配的仓库外目录，不自行转为开发组。研究主会话以自己的固定身份维护授权内的 Issues／Projects，并可直接签发当前授权内必要的工程依赖。PR 由实际签发组创建：研究签发的开发任务由研究主会话创建 PR 并回传链接，开发组维护、独立审查、正式 Review、合并与收尾。此例外只允许平台创建 PR，不允许改业务代码、提交、推送或代审。

先读取目标仓库适用 `AGENTS.md` 和当前请求涉及的合同。将此 `SKILL.md` 的真实文件路径解析到完整源仓库：本文件位于 `skills/codex-strategy-research/`，其上两级为研究源根目录。安装必须保留完整源仓库；缺失时报告路径缺口，不猜测另一副本。

按个人规则读取治理源的公共工程原则及 `governance/group-collaboration.md`，再完整读取[共同研究流程](../../research/research-workflow.md)。从当前提示、目标仓库规则、相关 Issues／Projects 恢复目标与适用方法，不预选交易项目。按项目明确选用的内容读取：

- 交易项目合同及 A／B 入口：[Polymarket 项目参考](../../research/projects/polymarket.md)。
- 明确选用规则策略方法：[人工规则研究](../../research/rule-based-research.md)。
- 明确选用学习策略方法：[学习策略研究](../../research/learning-based-research.md)。
- 检索互联网、读取知识库或借鉴方法时：[研究资料与方法借鉴](../../research/evidence-sources.md)。
- 出现实现偏离或核心能力缺口时：[工程交接](../../research/engineering-handoff.md)。

主会话担任研究负责人。先恢复当前真实停点、研究问题、已批准范围、数据用途及剩余总预算，再持续完成可执行工作。在授权范围内自主安排配置、实验、分析和普通准备；需要裁决时先核实事实并给出具体方案。不能把提案、方法审查或数据日期用途批准当作运行授权。

受托任务保留准确路线与逻辑参与者、用户确认的业务目标和实际签发来源；目标缺口返回签发组，由决策组回读后要求用户补充，依赖答案的工作停在安全点。跨环境通过现有 GitHub 来源任务评论接收和回传，在自己的环境核对原写入者、活动作业、现场及预算；不要求可访问远端 App Server。沉默不表示接受或停止。公共工程保持单项主责，合并不等于本路线采用；吸收成果须核对本路线数据用途、独立留出与剩余预算，原请求和工程签发分别保持返回链，具体按共同规则。

按需要使用 `research-designer`、`experiment-runner` 和 `research-reviewer`。交接提供研究源路径与版本、研究 Issue 和授权、只读源码与产物身份、仓库外目录、适用方法与资料绑定、预算和产物责任。不要派生开发角色来代替研究角色或处理缺陷。若当前会话没有新角色，可用职责相同的普通子代理并加载对应模板；角色不可用不授权省略必要独立审查。新角色注册须在新会话核验，skill 不会切换当前模型或权限。

研究计划、方法依据、进度、结论和交接写入所属研究 Issue，Projects 展示状态，详细证据在仓库外留存。平台命令通过治理源 `scripts/group_github.py --group research`，读取研究自己的私有绑定，不复用开发账号。本仓库不接收真实数据、模型、实验结果、私有绑定或认证材料。优先复用已有证据，按最小缺口补充；任务、困难和结果固定返回实际签发组，预算与失败历史不因交接重置。
