# 策略研究与探索

`codex-strategy-research` 用于通用研究与探索。它从目标项目恢复问题、假设、方法、对照、数据用途、预算与停止条件，在授权内执行实验和分析，由独立研究审查核对结论。交易合同与 A／B 方法保留为项目明确选用的参考。

本仓库是私有规则源。它不保存真实数据、模型、实验结果或个人配置，也不替代目标项目的合同。研究组对业务仓库全部文件与 Git 内容只读；仓库外研究产物可写，研究主会话按授权维护 Issues／Projects。当前授权内必要工程依赖由研究组直接签发开发组，结果直接回研究组。PR 由实际签发组创建，开发组以自己的固定身份维护、独立审查、正式批准、合并和收尾；超出授权时交用户。

项目可按路线设置独立决策组，并通过现有 GitHub 来源任务评论跨环境协作。研究接收准确逻辑参与者的委托，在自己的环境确认现场与预算；公共任务保持单项主责，公共合并与各路线采用分别判断。研究问题须支持用户确认的业务目标，目标缺口返回签发组澄清；吸收其他路线成果时，分别核对本路线的数据用途、独立留出资格和既有授权。

## 使用

按[安装说明](docs/installation.md)安装后，普通启动即可，无需 `--profile`：

```bash
codex -C /absolute/path/to/business-repository
```

在新会话中输入 `$`，从候选列表选择 `codex-strategy-research`，再追加研究请求。例如：

```text
$codex-strategy-research
推进当前已批准的研究问题。先核对任务当前合同、已批准范围、数据用途和剩余预算。
在已有授权内自主准备、实验和分析；尚未批准的运行只准备具体提案。
```

可明确选用项目特有方法。调用 skill 不提供新的运行预算，不启动训练服务器，不改变主会话的模型、推理等级或权限。研究职责需要显式调用，或研究流程接受已获用户授权的决策组明确委托；后续子任务沿用同一轮授权，不要求用户重复调用。

在非交互入口中，仅传入字面 `$codex-strategy-research` 可能未展开正文；使用客户端正式 skill 选择或结构化 skill 输入。已核实的版本差异和只读验证方式见[安装说明](docs/installation.md)，不要为绕过该限制打开隐式调用。

## 工作方式

用户按研究问题批准一轮范围与总预算。主会话在范围内决定具体实验、并行安排和分析；发生范围、预算、数据用途、业务语义、评价条件、资源或资金承诺等实质变化，或触发适用停止条件时，按[共同研究流程](research/research-workflow.md)交用户决定。一次亏损、无成交或训练没有改善，可以是有效研究结果。

| 职责 | 负责什么 |
| --- | --- |
| 主会话 | 保持问题、授权、证据与预算连续；协调实验，维护任务事实，提出结论和最少裁决事项 |
| `research-designer` | 只读设计假设、反例、对照和证据需求 |
| `experiment-runner` | 只在仓库外准备获批配置、辅助分析、实验和产物，保留原始证据与实际成本 |
| `research-reviewer` | 独立只读审查数据资格、偏差、可比性、经营解释和外推边界 |

不要求每个小实验都走固定三角色流水线。不同项目共用角色，按项目明确选用的方法加载。研究主会话可直接签发授权内工程依赖并创建相应 PR，但不能自行转开发或修改业务代码；子角色只向研究主会话返回证据。研究 Issue 保持当前约定与结论，评论保留方法和实验经过，Projects 展示进度，详细材料留在仓库外。

## 规则入口

- [共同研究流程](research/research-workflow.md)：授权、研究轮次、数据、硬件与并行安排、预算、停止、证据、结论及产物清理。
- [交易项目参考](research/projects/polymarket.md)：仅在项目明确选用时加载交易合同与 A／B 入口。
- [A：人工规则策略](research/rule-based-research.md)：机制、候选、解释性对照与经营证据。
- [B：学习策略](research/learning-based-research.md)：训练、模型选择、泄漏、随机性与冻结评价。
- [研究资料与方法借鉴](research/evidence-sources.md)：按问题使用互联网与项目知识库，核对原文、版本、证据状态和适用性。
- [工程交接](research/engineering-handoff.md)：缺陷证据、影响范围、修复与研究恢复。
- [案例验证](evaluations/scenarios.md)：用实际行为检查规则，不只检查文件格式。

`codex-governance` 继续维护通用工程原则和代码交付；本仓库维护研究方法；目标项目继续维护业务合同与研究结果。方法参考量化研究和机器学习一手资料，具体采用理由与适用局限见对应正文。

项目明确选用该知识库时，研究可按问题自主查阅互联网和 [research-knowledge](https://github.com/slowchillchill/research-knowledge)。本地知识库默认只读查询仓库外绑定的唯一 `main` 工作树，并固定核对提交与输入版本；维护者在论文提交推送后同步默认版本，显式历史查询从归档恢复。安装说明给出位置与版本的配置方法。人工收录、论文报告和本项目复现是不同证据层次，研究不自动回写知识库。

更新本仓库后，在研究记录中明确采用的新版本及影响。已开始的一轮研究不能因 skill 更新而静默改变评价口径。安装、更新与回滚遵守[安装说明](docs/installation.md)。
